# Internationalization

This page is the short index for the locale system. It explains the supported languages, the main source files, and the behaviors that matter when you are changing localized text or search input handling.

## Supported Locales

- `en`
- `es`
- `fr`
- `de`
- `it`
- `pt`
- `ja`
- `ko`
- `ru`
- `zhs`
- `zht`

## Canonical Files

- `src/lib/i18n/index.tsx`
- `src/lib/i18n/constants.ts`
- `src/lib/i18n/*.json`

## Key Behavior

- English is the fallback source of truth.
- Locale is persisted in `localStorage`.
- Search requests can carry locale into semantic-search.
- Scryfall uses locale mapping for localized card results.

## How The System Works

The i18n layer is mostly about presentation and input handling, not changing the underlying search semantics.

1. The UI reads the active locale.
2. Localized strings are resolved from the translation files.
3. Search input can carry locale information into the search pipeline.
4. The backend or Scryfall layer returns locale-aware content where possible.

The important constraint is that the deterministic search layer still expects English-like MTG phrasing. Localization helps the user experience, but it does not rewrite the underlying search rules.

## When To Edit The i18n Layer

- Add or update translation strings when UI text changes.
- Update the locale constants when adding a supported language.
- Review search-related components and hooks when locale should influence input behavior.
